# ゆくえ（仮称）

国のお金の流れと、政策・法律・制度・補助金の動きを、ひとつの場所で追えるようにするアプリです。
各府省にばらばらに出る発表を毎日集めて、同じ形にそろえ、画面とAIの両方から使えるようにします。

リポジトリ直下の既存アプリ（Global Money Flow）とは別のプロジェクトで、コードもデータもこのフォルダーの中で完結しています。

```
yukue/
  shared/types.ts   データの形（収集システムと画面が共有する約束ごと）
  data/             画面が読むデータ（JSON）。収集システムが毎日書きかえる
  collector/        収集システム（RSS・公開API・ページの巡回）
  web/              画面（React）
```

デザインの見本は `design/yukue-sample/index.html`（1ファイルで開ける試作）にあります。

## 動かす

Node.js 22.18 以上が必要です（収集システムが TypeScript をそのまま実行するため）。

画面を手元で開く：

```bash
cd yukue/web
npm install
npm run dev
```

いまの情報を集め直す：

```bash
cd yukue/collector
npm install
npm run collect
```

`npm run collect` は `yukue/data` を書きかえます。開発サーバーは `yukue/data` をそのまま配信するので、集め直したあとは画面を読み込み直すだけで反映されます。

画面のくわしい説明（中身の構成、ビルド、ブラウザーでの確認）は [`web/README.md`](web/README.md) にあります。

## 収集システム

### 何を集めているか

`npm run collect` を実行すると、登録してある情報源を順に回ります。一覧は `node src/cli.ts sources` で見られます。

| 取り方 | 情報源 |
| --- | --- |
| RSS | 首相官邸、財務省、厚生労働省、総務省、内閣府、文部科学省、国土交通省、農林水産省、金融庁、消費者庁、デジタル庁、防衛省、e-Gov パブリック・コメント |
| 新着ページの巡回 | 環境省、こども家庭庁、国税庁、法務省、会計検査院（フィードがない府省） |
| ページの巡回（専用の読み方） | 首相官邸の閣議案件、衆議院の議案情報（法案ごとの審議の経過） |
| 公開API | Jグランツ（受付中の補助金） |

経済産業省・外務省・公正取引委員会は、自動の取得に 403 を返すため入れていません（経済産業省の補助金は、Jグランツ経由で一部が入ります）。

新着ページの巡回（`src/sources/list.ts`）は、ページに並ぶ「リンクと、その項目の日付」を組にして読みます。表、リスト、日付の見出しの下にまとめた形など、サイトごとの作りのちがいを吸収するためのものです。

### 相手に負担をかけないための決まり

- `robots.txt` を確かめ、禁止されている場所は取りに行きません。確かめられないとき（5xx）は、その回の取得を見送ります
- 同じホストには1本ずつ、1.5秒以上あけて取りに行きます（`Crawl-delay` のほうが長ければそちら）
- 前回から変わっていなければ本文を受け取りません（`ETag` / `Last-Modified`、中身のハッシュ）
- やり直すのは一時的な失敗（429・5xx・通信エラー）だけで、最大2回です
- 名乗り（User-Agent）は `yukue-collector/0.1`。本番では、連絡先のURLを入れたものを `YUKUE_USER_AGENT` に設定してください

2回目以降は「変わったところだけ」を取りに行くので、1回の実行は通信30〜50回・1〜2分ほどです。

### 集めたあとの整理

1. **分類**（`src/classify.ts`）：題と発表元から、種類（法律・予算・税・制度・補助金・その他）、分野、いまの段階、重要度を決めます。人事・入札・会議資料の掲載といった定型の発表には印を付け、画面の既定の表示からは外します
2. **重ね合わせ**（`src/store.ts`）：前回までの一覧に重ねます。同じ発表は1件にまとめ、閣議で公布が決まった法律は国会の議案の項目に合流させます
3. **残す期間**：重要度50以上は60日、40〜49は45日、それ未満は21日、定型の発表は7日。一覧から外れたものも `data/updates/archive/` には残ります
4. **きょうの3件**（`data/briefing.json`）：直近3日のうち、重要度の高いものから選びます

分類は規則によるもので、取りこぼしや誤りがあります。規則を直したら、通信をせずに手元のデータへ当て直せます。

```bash
node src/cli.ts reclassify --dry-run   # 何が変わるかを見る
node src/cli.ts reclassify             # 当て直す
node src/cli.ts rebuild                # 残す期間の決まりを変えたとき、保管分から一覧を作り直す
```

### AIによる整形（任意）

`ANTHROPIC_API_KEY` を設定すると、重要度の高い項目について発表ページの本文を読み、分かりやすい題・要約・「何が変わる／だれに関係／いつから」を作ります（`src/enrich.ts`）。設定しなければ、この段は飛ばします。

- 与えた題と本文だけを根拠にし、本文にない数字や評価は足さないよう指示しています
- 1回の実行で整えるのは最大25件（`YUKUE_ENRICH_LIMIT`）。一度整えた項目は、段階が進むまで作り直しません
- モデルは `YUKUE_MODEL` で変えられます

AIが整えた項目は `enriched: "ai"` となり、画面ではそのことが分かるように表示します。

#### モデルを選ぶ

使うモデルは `YUKUE_MODEL` で切り替えます（例：`claude-haiku-5-5`、`claude-sonnet-5-5`）。切り替える前に、同じ項目で読み比べられます。

```bash
node src/cli.ts compare --models claude-haiku-5-5,claude-sonnet-5-5 --limit 10
```

一覧には書き込まず、`compare-report.md` に、項目ごとの結果を横に並べた報告を作ります。モデルごとのトークン数と費用、そして「整形した文に、もとの題と本文に見当たらない数字が出ていないか」の確認も付きます。GitHub では、Actions の「Yukue compare models」から手動で実行できます（main に入ってから）。

### 情報源を増やす

```bash
npm run discover -- https://www.example.go.jp/
```

ページからフィード（RSS・Atom）を探し、読めるかを確かめます。フィードがないページでは、新着の並び（日付とリンク）を何件読み取れるかを表示します。確かめたら `src/sources/registry.ts` に1行足します。

- フィードがあれば `RSS_FEEDS` へ
- なければ `LIST_PAGES` へ。メニューなどを拾うページでは、`scope`（読む範囲）や `link`（対象のリンク）をCSSセレクターで指定します

### 失敗に気づく

- 情報源は1つずつ独立していて、どれかが失敗しても残りは続けます。情報源ごとの結果は `data/runs/latest.json` に残り、画面の「このサイトについて」に表示されます
- 閣議案件や議案のように何ページも読む情報源は、途中で失敗しても、そこまでに読めた分を生かし、残りを次の実行で読みます
- ページの作りが変わって1件も読み取れなくなったときは、空のデータで上書きせず、失敗として記録します
- `node src/cli.ts health` は、同じ情報源が続けて失敗しているとき（既定は6回）に終了コード1を返します

### 設定（環境変数）

| 名前 | 既定 | 内容 |
| --- | --- | --- |
| `YUKUE_USER_AGENT` | `yukue-collector/0.1 (public-data aggregator)` | 相手のサーバーへの名乗り |
| `YUKUE_MIN_INTERVAL_MS` | `1500` | 同じホストへの取得の間隔（500未満にはできません） |
| `YUKUE_TIMEOUT_MS` | `30000` | 1回の取得の制限時間 |
| `YUKUE_DATA_DIR` | `yukue/data` | 書き出し先 |
| `ANTHROPIC_API_KEY` | なし | あるときだけ、AIによる整形を行う |
| `YUKUE_MODEL` | `claude-opus-5-5` | 整形に使うモデル |
| `YUKUE_ENRICH_LIMIT` | `25` | 1回の実行でAIが整える件数の上限（0で止める） |

## 毎日の自動実行

`.github/workflows/yukue-collect.yml` が、毎日 6:17 と 18:17（日本時間）に収集を実行し、変わった分を `yukue/data` にコミットします。

- **予定どおりに動くのは、このファイルが既定のブランチ（main）に入ってから**です。それまでは動きません
- GitHub の Actions の画面から、手動でも実行できます（情報源をしぼる、書き出さずに試す、が選べます）
- リポジトリの設定（Settings → Secrets and variables → Actions）で、次を入れられます。どれも任意です
  - Secrets：`ANTHROPIC_API_KEY`
  - Variables：`YUKUE_USER_AGENT`、`YUKUE_MODEL`、`YUKUE_ENRICH_LIMIT`
- main に「プルリクエストを必須にする」保護をかけている場合、このワークフローからの直接のコミットは拒否されます。その場合は、保護の例外に GitHub Actions を加えるか、データ用のブランチに書き出す形に変えてください
- 実行のたびに、情報源ごとの結果の表が Actions のまとめのページに出ます。同じ情報源が6回続けて失敗すると、その実行は失敗として通知されます

`.github/workflows/yukue-ci.yml` は、`yukue/` 以下を変更した push のたびに、型検査・テスト・ビルドを行います。

## データ

`yukue/data` の JSON は、すべて `shared/types.ts` の型に従います。

| ファイル | 書く人 | 内容 |
| --- | --- | --- |
| `budget/fy2026.json` | 人 | 令和8年度一般会計の歳入・歳出と内訳（財務省の資料から） |
| `updates/curated.json` | 人 | 人が確かめて書いた動き。収集分より優先して表示する |
| `programs/curated.json` | 人 | 個人・事業者向けの主な制度（対象の条件つき） |
| `calendar.json` | 人 | これからの予定 |
| `updates/latest.json` | 収集システム | 画面に出す動きの一覧（人が書いた分＋集めた分） |
| `updates/archive/YYYY-MM.json` | 収集システム | 月ごとの保管用。一覧から外れたものも残る |
| `briefing.json` | 収集システム | きょうの3件 |
| `programs/jgrants.json` | 収集システム | Jグランツで受付中の補助金 |
| `runs/latest.json` | 収集システム | 前回の実行の、情報源ごとの結果 |
| `state/*.json` | 収集システム | 次の実行で差分だけを取るための記録（画面には出さない） |

人が書くファイルは、収集システムが書きかえることはありません。

## まだないもの

- ウォッチ（追っている案件・待ち受け・締切を置いておき、動きがあったときに知らせる）。画面の案は、デザインの見本に入っています
- AIチャットの裏側（いまの画面のチャットは、手元のデータだけで答える簡易版です）
- 外部のAIから使うための接続口（MCPサーバー）
- ログインと、端末をまたいだ設定の同期（いまは、設定はその端末のブラウザーにだけ保存されます）
- 予算の内訳より先（事業ごとの支出先）と、過去の年度
